# Работа с MINT

- Сначала прочитай [CONTRIBUTING.md](CONTRIBUTING.md) и [docs/CODE_MAP.md](docs/CODE_MAP.md).
- Карта — навигатор по исходникам, данным и тестам. Сверь её базовый коммит с текущим кодом; при расхождении изучи diff, нужные модули и зависимости. Код определяет фактическое поведение.
- Соблюдай разделение ядра `mint/` и интерфейса `mint/ui/`, правила RU/EN текстов и промптов из CONTRIBUTING.
- Для изменения поведения добавляй регрессионную проверку; выполни `python tests/run_all.py` и подходящие интеграционные проверки.
- Не добавляй в Git секреты, рабочие настройки, пользовательские документы, базы или логи.
- При изменении структуры, точек входа, форматов данных или тестов актуализируй `docs/CODE_MAP.md` в том же PR. Указывай проверенный базовый SHA (до собственного коммита); не пытайся угадать будущий SHA.
- **Перед каждым релизом обязательно вручную:** сравни `docs/CODE_MAP.md` с актуальным кодом и обнови проверенную основу; сверяй обе схемы по фактическому коду. При изменениях обнови генераторы `tools/diagrams/`, RU/EN подписи, `.excalidraw`, `.excalidraw.md` и PNG; при новом теге синхронизируй `release/manifest.json`, `DIAGRAM_RELEASE` и `MINT_VERSION`. Запускай `python tests/test_diagrams.py` и `python tools/diagrams/check_release.py` **вручную**, фиксируй результаты в PR/отчёте. Автогенерации и проверок карты/схем в GitHub Actions нет: их не добавлять без отдельного решения пользователя.
- В отчёте разделяй локальные проверки, результаты CI и проверку пользователем. Прошедшие тесты с имитацией моделей не доказывают качество ответов на рабочей базе.
