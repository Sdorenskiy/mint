# MINT: описание для согласования с ИБ

[English: Security](../SECURITY.md) · **Русский**

Черновик для заявки на установку. Пункты «уточнить» заполняет владелец установки.

## 1. Назначение

MINT — инструмент для сотрудников, работающих с внутренними документами. Он умеет три вещи:

- отвечает на вопросы по базе загруженных документов со ссылками на источники;
- проверяет документ на согласование по критериям и нормам из базы;
- проверяет, устранены ли замечания в новой редакции документа.

Результаты — рекомендации для эксперта. Решения принимает человек.

## 2. Состав и потоки данных

```
Браузер пользователя ──HTTP, localhost──► MINT (Python, Streamlit) ──HTTPS──► шлюз моделей компании
                                              │                              (LLM, эмбеддинги, реранкер)
                                              └── локальные файлы: база знаний, логи, отзывы
```

- **Исходящие соединения** — только к адресам из `.env`: API языковой модели, эмбеддингов и реранкера
  (уточнить: шлюз, модели). Других обращений в сеть MINT не делает:
  - сбор статистики Streamlit отключён (`.streamlit/config.toml`: `gatherUsageStats = false`);
  - страница ничего не загружает из интернета: шрифты интерфейса лежат в `static/fonts/` и раздаются самим
    Streamlit (`enableStaticServing = true`; раздаётся только папка `static/`, по адресу `app/static/`);
  - документы принимаются только в формате .docx. Для них Docling не использует нейросетевые модели и
    не загружает их из интернета (проверить в песочнице: `check_install.py` без доступа в интернет).
- **Входящие соединения** — по умолчанию нет: страница слушает только `localhost:8501`
  (`server.address = "localhost"`) и не видна с других компьютеров.
- **Что уходит в модели:**
  - фрагменты документов из базы и проверяемого документа;
  - вопросы пользователя;
  - тексты замечаний.

  Если в документах есть персональные данные или иная защищаемая информация, шлюз должен быть
  разрешён для неё.

## 3. Что и где хранится

| Где | Что | Содержит текст документов |
|---|---|---|
| `KB_DIR` (по умолчанию `~/knowledge_base`) | фрагменты документов (`parent_store.json`), векторы (FAISS), индекс BM25, метаданные, оригиналы загруженных .docx (`sources/`), найденные сокращения | да |
| `LOG_DIR` (по умолчанию `~/mint_logs`) | журнал работы `mint_system.log` (ротация 10 МБ × 5): начала запросов (до 120 символов), имена файлов, ошибки | частично |
| `LOG_DIR/feedback.jsonl` | оценки 👍/👎 с вопросом, ответом, источниками и комментарием | да |
| `LOG_DIR/eval/` | проверки качества: вопросы с дословными фразами из документов, отчёты, ответы чата | да |
| `LOG_DIR/audits/` | сохранённые аудиты («📂 Мои аудиты»): заключение, лог, сырые ответы модели (сжаты), копия проверенного .docx, разбор замечаний экспертом; удаляются кнопкой «🗑️ Удалить аудит» | да |
| `.env` в папке программы | адреса API и **ключ доступа** | нет |
| `prompts.yaml` в папке программы (`PROMPTS_PATH`) | свои правки промптов моделей, сохранённые на странице «📝 Промпты» | нет |
| память процесса | история чата и результаты проверок текущего сеанса; удаляются при закрытии вкладки и перезапуске | да |

Файл разбора для улучшения MINT («📤 Скачать разбор», «📥 Скачать разборы») пользователь скачивает сам. С
текстами (по умолчанию) в нём замечания с цитатами документа; с флажком «Без текстов замечаний» — только виды
проверок, критичность, отметки и причины, без текстов, цитат, разделов, комментариев и имён файлов.

Рекомендации:

- права на `KB_DIR`, `LOG_DIR` и `.env` — только у учётной записи, под которой работает MINT
  (`chmod 700` на папки, `chmod 600` на `.env`);
- правку промпта для всех может сохранить любой, кто открывает MINT («📝 Промпты» → «Сохранить»); версия
  промптов и список изменённых пишутся в отзывы, лог аудита и проверки качества. На общем сервере, если правки
  должен вносить администратор, сделайте `prompts.yaml` доступным учётной записи MINT только для чтения:
  страница сообщит, что сохранить не удалось, а «Попробовать в сеансе» по-прежнему работает;
- файлы базы `*.pkl` читаются модулем pickle — запись в эту папку посторонним недопустима;
- резервное копирование `KB_DIR` — по правилам для документов такой категории (уточнить).

## 4. Секреты

- Ключ доступа к моделям хранится в `.env`; в репозиторий этот файл не попадает (`.gitignore`).
- MINT не пишет ключи в журнал. Самопроверка `check_install.py` показывает только, задан ли ключ.
- Проверка TLS-сертификатов включена. Корпоративный CA задаётся в `CA_BUNDLE_PATH`, в Windows
  используется хранилище сертификатов ОС. Отключение проверки (`SSL_INSECURE=1`) — только для отладки во
  внутренней сети; при этом MINT пишет предупреждение в журнал.

## 5. Зависимости

| Пакет | Назначение | Лицензия |
|---|---|---|
| Streamlit | веб-интерфейс | Apache 2.0 |
| Docling (облегчённая сборка `docling-slim`, только разбор .docx: без PyTorch и моделей) | разбор .docx | MIT |
| faiss-cpu | векторный поиск | MIT |
| NumPy | вычисления | BSD |
| requests | HTTPS-запросы к API | Apache 2.0 |
| python-docx | чтение и запись .docx | MIT |
| python-dotenv | чтение `.env` | BSD |
| PyYAML | чтение промптов моделей (`mint/prompts/*.yaml`) и `config.yaml` | MIT |
| pdfplumber (с pdfminer.six и pypdfium2) | разбор .pdf по текстовому слою, без моделей; в сеть не обращается | MIT; pypdfium2: Apache 2.0 / BSD-3 |
| truststore | сертификаты из хранилища ОС | MIT |

Точные версии фиксируются в `requirements.lock`. Пакеты ставятся из внутреннего зеркала PyPI или
офлайн-комплекта и проверяются по процедуре компании (уточнить).

## 6. Известные риски и ограничения

- **Нет аутентификации и разграничения доступа.** В локальном режиме это не проблема: страница доступна
  только на компьютере пользователя. Для общего стенда см. раздел 7.
- **Общая база на экземпляр.** Все пользователи одного экземпляра работают с одной базой знаний.
  Проверяемые документы, история чата и заключения у каждого пользователя свои и хранятся в памяти его
  сеанса.
- **Инструкции внутри документов** (prompt injection). Текст документа может повлиять на ответ модели.
  Поэтому результаты — рекомендации, а ссылки на источники позволяют их проверить.
- **Ошибки модели.** Модель может пропустить замечание или ошибиться. Аудит не заменяет экспертизу.

## 7. Развёртывание на стенде (план)

| Мера | Как |
|---|---|
| Изоляция | Отдельная ВМ или контейнер (`Dockerfile`), служебная учётная запись без прав администратора |
| Доступ | Обратный прокси (nginx и т. п.) с корпоративной аутентификацией (SSO/LDAP) и TLS. MINT слушает только `127.0.0.1` за прокси |
| Сеть | Исходящие соединения — только к шлюзу моделей; входящие — только от прокси |
| Streamlit | `server.address = "127.0.0.1"`, `server.fileWatcherType = "none"`, `server.maxUploadSize` по необходимости; защита от XSRF включена по умолчанию (`server.enableXsrfProtection`) |
| Данные | Права на `KB_DIR`, `LOG_DIR` и `.env` — только у служебной учётной записи; резервное копирование базы; ротация журналов |
| Обновления | Новая версия — через песочницу компании; версии пакетов фиксированы в `requirements.lock` |
| Разделение баз | Если документы разных подразделений нельзя смешивать — отдельный экземпляр со своим `KB_DIR` на каждое |

## 8. Контакты

Владелец и разработчик: уточнить. Исходный код: публичный репозиторий GitHub.
Рабочие документы, база знаний, журналы и ключи в репозиторий не попадают.
