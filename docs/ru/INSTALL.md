# Установка MINT на рабочий компьютер

[English](../INSTALL.md) · **Русский**

MINT работает на вашем компьютере: страница открывается в браузере по адресу `http://localhost:8501` и
видна только вам. Документы и база знаний остаются на этом компьютере. Наружу MINT обращается только к
API моделей, адреса которых вы впишете в `.env`.

Права администратора не нужны: всё ставится в папку `.venv` рядом с программой.

**Коротко:**

1. Python 3.10 или новее.
2. Папка MINT.
3. `install.sh` (Linux) или `install.bat` (Windows).
4. Заполнить `.env`.
5. Запустить `run_mint.sh` или `run_mint.bat`.

## Зачем install.sh и run_mint.sh

MINT — программа на Python. Ей нужны сторонние пакеты: Streamlit (страница в браузере), Docling (разбор
.docx), faiss (векторный поиск) и ещё несколько. Без них `streamlit run app.py` не запустится. Разработчик
поставил их один раз вручную через pip; скрипты делают то же самое за коллегу, одной командой.

| Скрипт | Что делает | То же вручную |
|---|---|---|
| `install.sh` / `install.bat` | проверяет Python (нужен 3.10+) → создаёт рядом с программой папку `.venv` → ставит в неё пакеты точных версий из `requirements.lock` (из интернета, зеркала или офлайн-комплекта); неполную `.venv` от прерванной установки создаёт заново → создаёт `.env` из образца → запускает самопроверку | `python3 -m venv .venv`<br>`.venv/bin/pip install -r requirements.lock`<br>`cp .env.example .env`<br>`.venv/bin/python check_install.py` |
| `run_mint.sh` / `run_mint.bat` | переходит в папку MINT → запускает Streamlit из `.venv` → открывает браузер | `cd ~/mint`<br>`.venv/bin/python -m streamlit run app.py` |

**Почему `.venv`, а не просто `pip install`:**

- без прав администратора pip не может ставить пакеты в систему, а в папку пользователя — может;
- версии пакетов MINT не конфликтуют с другими программами на Python;
- система не меняется: удалить MINT — удалить папку.

**Можно запускать без скриптов**, если пакеты уже стоят (как у разработчика):

```bash
cd ~/mint
streamlit run app.py        # раньше: streamlit run web_app_v19.py
```

Две оговорки:

- `python app.py` не сработает: приложения Streamlit запускаются командой `streamlit run`.
- Запускайте из папки MINT. Иначе Streamlit не увидит `.streamlit/config.toml`, и страница станет доступна по
  сети, а не только на вашем компьютере.

## Что понадобится

| | |
|---|---|
| Python | **3.10–3.12** (рекомендуется 3.11). Python 3.7–3.9 не подойдёт: Docling их не поддерживает |
| Диск | ≈ 0,6 ГБ на пакеты, скачивается ≈ 165 МБ (без PyTorch, см. [«Версии пакетов и Docling без PyTorch»](#версии-пакетов-и-docling-без-pytorch)). Плюс место под базу знаний |
| Память | от 4 ГБ свободной; большие документы разбираются дольше |
| Доступ к моделям | адреса API языковой модели и эмбеддингов и **свой** ключ |
| Пакеты Python | из интернета, внутреннего зеркала PyPI или офлайн-комплекта (см. ниже) |

> **Модели — только разрешённые.** В `.env` указываются только модели и шлюзы, которые разрешено
> использовать для ваших документов. Ключ личный: не передавайте его и не кладите `.env` в общие папки.

Папку MINT лучше положить по короткому пути без пробелов — например `~/mint` или `C:\mint`. Пути с
кириллицей MINT поддерживает, но отдельные пакеты Python на Windows с ними капризны.

## Astra Linux

### 1. Проверьте версию и Python

```bash
cat /etc/astra_version
python3 --version
```

- **Astra Linux 1.8** — Python 3.11, подходит.
- **Astra Linux 1.7** — Python 3.7, MINT на нём не запустится. Варианты: обновление до 1.8, Python 3.10+,
  установленный администратором (тогда `PYTHON=/путь/к/python3.11 ./install.sh`), или работа на другом
  компьютере / общем стенде.

### 2. Замкнутая программная среда (ЗПС)

Если на компьютере включена ЗПС, библиотеки из pip (numpy, faiss и другие) не подписаны и не загрузятся
(ошибка вида `Operation not permitted` при импорте). Самопроверка `check_install.py` сообщит об этом.
Решение — только через администратора (подпись библиотек или исключение для папки MINT). Обходить ЗПС
не нужно.

### 3. Установка

```bash
cd ~/mint
./install.sh            # пакеты из интернета или внутреннего зеркала
./install.sh wheels     # без интернета: из офлайн-комплекта (папка wheels)
```

Скрипт создаёт `.venv`, ставит пакеты точных версий из `requirements.lock`, создаёт `.env` из образца и
запускает самопроверку. Если в системе нет пакета `python3-venv`, скрипт создаст окружение без него, а pip
скачает системным pip (по вашим настройкам зеркала) или возьмёт из офлайн-комплекта — администратор не нужен.
Неполную `.venv` от прерванной попытки скрипт создаёт заново сам; начать с нуля — `./install.sh --clean`.

Если pip не выходит в интернет, но в компании есть внутреннее зеркало PyPI (Nexus, Artifactory — адрес
подскажут ИТ):

```bash
python3 -m pip config set global.index-url https://<адрес-зеркала>/simple
python3 -m pip config set global.cert /путь/к/корпоративному-ca.crt   # если зеркало на внутреннем сертификате
```

## Windows

> Windows разработчик пока не тестировал. Если что-то не работает, пришлите вывод `check_install.py`.

### 1. Python

Установите Python 3.11 или 3.12 с [python.org](https://www.python.org/downloads/windows/). Выберите
вариант **«Install for me only»** (права администратора не нужны). Проверка в командной строке:

```bat
py -3 --version
```

### 2. Установка

Распакуйте MINT, например в `C:\mint`, и дважды щёлкните `install.bat`. Для офлайн-комплекта выполните в
командной строке из папки MINT:

```bat
install.bat wheels
```

Если запуск `.bat` запрещён политикой или антивирусом, выполните те же команды вручную:

```bat
cd C:\mint
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.lock
copy .env.example .env
.venv\Scripts\python check_install.py
.venv\Scripts\python -m streamlit run app.py
```

### 3. Корпоративные сертификаты

Внутренние шлюзы обычно работают на сертификате компании. В Windows MINT проверяет сертификаты по
хранилищу Windows (пакет `truststore`). Если всё равно появляется ошибка сертификата
(`CERTIFICATE_VERIFY_FAILED`):

1. Экспортируйте корневой сертификат компании в файл `.pem` (Base64).
2. Укажите путь к нему в `.env`: `CA_BUNDLE_PATH=C:\mint\corp-ca.pem`.

### 4. Файл `.env` в Блокноте

При сохранении выберите тип **«Все файлы»** и имя `.env`, иначе получится `.env.txt`, и MINT его не
увидит. Кодировка — UTF-8 или Windows-1251, обе подходят.

## Заполнить `.env`

Откройте `.env` в папке MINT (скрипт установки создал его из `.env.example`) и впишите:

```ini
LLM_API_URL=https://<шлюз>/v1                 # без /chat/completions
EMBED_API_URL=https://<шлюз>/v1/embeddings
LLM_API_KEY=<ваш ключ>
LLM_MODEL=<модель>                            # пусто — первая из списка шлюза
EMBED_MODEL=<модель эмбеддингов>
RERANK_API_URL=https://<шлюз>/v1/rerank       # необязательно, но повышает точность
RERANK_MODEL=<модель реранкера>
```

Остальное можно не трогать. База знаний по умолчанию хранится в `~/knowledge_base`, логи и отзывы — в
`~/mint_logs`. Язык интерфейса — как в системе; задать явно: `MINT_LANG=ru` (или `en`). Переключается и в
боковой панели.

## Проверить установку

```bash
.venv/bin/python check_install.py          # Linux
.venv\Scripts\python check_install.py      # Windows
```

Самопроверка проходит по шагам:

1. Python и пакеты.
2. Разбор тестового .docx.
3. `.env` и папки.
4. Связь с моделями, включая один короткий запрос к языковой модели (без него — `--no-llm`).
5. Настройки Streamlit.
6. Смоук-тест: страница MINT открывается на настоящем Streamlit без браузера (без него — `--skip-page`).

На каждую ошибку есть подсказка. Ключей в выводе нет — его можно переслать разработчику целиком.

## Запуск

```bash
./run_mint.sh        # Linux
run_mint.bat         # Windows — двойной щелчок
```

Браузер откроется сам, или откройте `http://localhost:8501`. Остановить — Ctrl+C (или закрыть окно
консоли).

Первые шаги:

1. Загрузите нормативные документы в базу (боковая панель → «База знаний»).
2. Задайте вопрос в чате.
3. Проверьте документ во вкладке «Аудит документа».

Оценивайте результаты кнопками 👍/👎 — отзывы копятся в `~/mint_logs/feedback.jsonl`, а файл можно скачать
в боковой панели («💬 Отзывы»).

> Отзывы содержат вопросы, ответы и цитаты из ваших документов — пересылайте файл только туда, куда
> можно передавать эти документы.

## Офлайн-комплект

Для коллег, у которых pip не выходит в интернет. Комплект собирают на компьютере с доступом к пакетам,
**с той же ОС и той же версией Python** (например, Astra 1.8 с Python 3.11 — для Astra 1.8).

Linux:

```bash
cd ~/mint
python3 -m pip download -r requirements.lock -d wheels     # или requirements.txt, если lock-файла нет
python3 -m pip download pip -d wheels                      # pip — для систем без python3-venv
```

Windows:

```bat
cd C:\mint
py -3 -m pip download -r requirements.lock -d wheels
```

Передайте папку MINT вместе с `wheels`, но **без** `.env`, `knowledge_base`, `mint_logs` и своих
документов. Передавайте её разрешённым в компании способом. Коллега запускает `./install.sh wheels` или
`install.bat wheels`.

Собрать комплект для Astra 1.8 на другой ОС можно так. Это работает, только если у всех пакетов есть
готовые колёса; если pip сообщит о пакете без колеса, соберите комплект на такой же машине:

```bash
python3 -m pip download -r requirements.lock -d wheels --only-binary=:all: \
    --platform manylinux_2_28_x86_64 --platform manylinux2014_x86_64 \
    --python-version 3.11 --implementation cp
```

## Версии пакетов и Docling без PyTorch

**Точные версии.** `install.sh` и `install.bat` ставят пакеты по `requirements.lock` — точные версии, одни для
Linux, Windows и macOS (с пометками для версий Python и ОС). Именно их проверяет GitHub при каждом изменении и
каждую ночь: установка с нуля на Ubuntu (Python 3.10–3.12), Debian 12 без `python3-venv` (как Astra Linux 1.8) и
Windows, затем разбор .docx настоящим Docling, база → чат → аудит и самопроверка
(`.github/workflows/install.yml`, `tests/test_real_install.py`). Если какой-то точной версии нет на вашем
зеркале, скрипт сообщит об этом и поставит пакеты по `requirements.txt`.

Обновить версии (для разработчика): поменять `requirements.txt` и пересобрать lock-файл, затем дождаться
зелёной проверки установки на GitHub:

```bash
pip install uv
uv pip compile requirements.txt --universal --python-version 3.10 --no-header -o requirements.lock
```

**Docling без PyTorch.** .docx разбирает Docling — его бэкенд Word: стили заголовков, списки, таблицы, без
моделей. MINT вызывает этот бэкенд напрямую, а не через общий конвертер Docling, который при запуске подгружает
и разбор PDF с моделями (PyTorch). Результат тот же, что у полного Docling через конвертер, — это сверяется на
GitHub на тестовых документах Docling и своих примерах (`tools/docx_parity.py`; проверить на своих документах:
`python tools/docx_parity.py папка_с_docx`, если у вас стоит полный Docling). Поэтому ставится облегчённая сборка
`docling-slim[format-docx]` точной версии:

| | MINT (облегчённый Docling) | с полным Docling |
|---|---|---|
| Пакетов | 72 | 122 |
| Скачивается | ≈ 165 МБ | ≈ 540 МБ (PyTorch для процессора) — гигабайты с PyTorch для видеокарты |
| На диске | ≈ 0,6 ГБ | ≈ 2,1 ГБ |
| Библиотеки моделей (PyTorch, transformers, huggingface_hub, OpenCV) | нет | есть |

Меньше пакетов — меньше проверять службе ИБ, и нет библиотек, которые умеют сами скачивать модели из
интернета. .pdf MINT читает своими силами (pdfplumber), тоже без моделей.

Если полный Docling у вас уже стоит (например, MINT запускается системным Python), ничего менять не нужно: MINT
берёт из него тот же бэкенд Word.

## Обновление

Остановите MINT и запустите в папке программы `update.sh` (Windows — `update.bat`) с архивом новой версии:

```bash
./update.sh ~/Загрузки/mint-21.2.zip        # или .tar.gz, или распакованная папка новой версии
```

Скрипт заменяет код (папки `mint`, `docs`, `tools`, `tests`, `static` — целиком, чтобы не остались удалённые
файлы), сохраняет ваши `.env`, `config.yaml`, `glossary.json`, `checklists.yaml`, `prompts.yaml` и `.venv` (из
архива они не берутся, даже если там есть) и сам запускает `install.sh`: доставит новые пакеты и проверит
установку. Без интернета — вторым аргументом папка офлайн-комплекта (`./update.sh mint.zip wheels`); если она
лежит в самой новой версии, скрипт найдёт её сам. Номер версии — внизу боковой панели («Версия MINT»).

Вручную: замените файлы программы новыми, не трогая перечисленные файлы, и выполните `./install.sh` ещё раз.

База знаний хранится отдельно (`KB_DIR`) и при обновлении не меняется. Если новая версия попросит
переиндексацию, это будет видно в боковой панели.

## Частые проблемы

| Сообщение | Что делать |
|---|---|
| `Port 8501 is already in use` | MINT уже запущен — откройте `http://localhost:8501`. Второй экземпляр: `./run_mint.sh --server.port 8502` |
| `.env не найден` | Файл должен называться ровно `.env` и лежать рядом с `app.py`. Самопроверка покажет, где MINT его искал |
| `CERTIFICATE_VERIFY_FAILED` | Укажите корпоративный сертификат в `CA_BUNDLE_PATH` (см. [«Корпоративные сертификаты»](#3-корпоративные-сертификаты)) |
| HTTP 401 / 403 | Неверный или просроченный ключ, либо нет доступа к модели |
| HTTP 404 | Неверный адрес: `LLM_API_URL` — база без `/chat/completions`, `EMBED_API_URL` — полный адрес `/embeddings` |
| `Operation not permitted` при импорте | Включена ЗПС — см. раздел [Astra Linux](#2-замкнутая-программная-среда-зпс) |
| `python` / `py` не найден (Windows) | Переустановите Python с python.org; лаунчер `py` ставится по умолчанию |
| Первая загрузка документа идёт долго | При первом запуске Docling загружается в память, дальше быстрее |
| `Incomplete .venv` / `No module named pip` | Осталась неполная `.venv` от прерванной установки — `install.sh` сам создаёт её заново; принудительно: `./install.sh --clean` |
| Нет пакета `python3-venv` | Администратор не нужен: `install.sh` скачает pip системным pip (по вашим настройкам зеркала). Если и системного pip нет — офлайн-комплект с `pip-*.whl` |
| `No module named 'torch'` или `'docling_parse'` при загрузке .docx | Пакеты стоят не по `requirements.lock` (другой Docling): `./install.sh --clean` (Windows — `install.bat --clean`) |
| `Some exact versions are not available` | На зеркале нет какой-то точной версии — скрипт сам поставит по `requirements.txt`; сообщите разработчику, какой пакет |
| Установка остановилась с ошибкой pip | На экране — конец журнала; полный вывод pip — в `.venv/install.log` (Windows — `.venv\install.log`), его и пришлите |
| `GOST engine already loaded` | Сообщение системной криптографии Astra (движок ГОСТ в OpenSSL), не MINT; на работу не влияет |
