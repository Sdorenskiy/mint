# Эталонный замер качества аудита и черновика (PR #20–21)

**Назначение.** Отделить проверку *работы программных ограничителей* от измерения *качества LLM и поиска*. Без ручной разметки и одинаковых входных документов нельзя заявлять об улучшении реального аудита.

## Данные и запуск

- 40 полностью выдуманных случаев сверки требования с утверждением: tests/fixtures/document_evidence_golden.jsonl (20 для аудита и 20 для черновика). Есть настоящие конфликты, соответствие, чужая система, неопределённая применимость, ложные цитаты, номера таблиц и намеренно ошибочная уверенная применимость.
- 8 искусственных матриц черновика (tests/fixtures/draft_coverage_golden.jsonl), всего 26 требований: отражённые, пропущенные, неприменимые, не найденные поиском и ошибочно отмеченные «использованными».
- Сценарии размечены **до запуска проверки**, gold_conflict и applicable/reflected не зависят от ответов модели. Поле model содержит **сценарный (подставной)** ответ, а не результат реального шлюза.

Один локальный запуск (без сети и LLM):

    python tests/eval_document_quality.py

Сохранить Markdown и JSON-отчёт **только локально**:

    python tests/eval_document_quality.py --report-dir ./local_eval/first

Сравнить с тем же набором/методикой:

    python tests/eval_document_quality.py --report-dir ./local_eval/second --baseline ./local_eval/first/document_quality.json

Чтобы проверять реальные выходы новой/старой версии модели, подать **полные ответы** отдельно:

    python tests/eval_document_quality.py --predictions ./local_eval/model_predictions.jsonl --report-dir ./local_eval/model-run

Файл model_predictions.jsonl содержит ровно по одной строке на каждый ID E01–E40:

    {"id":"E01","model":{"status":"conflict","ref":"N1","claim_quote":"...","norm_quote":"...","scope_quote":"точная цитата из проверяемого документа об области применения","applicability":"applicable","applicability_reason":"...","reason":"..."}}

Все 40 записей обязательны; неполные/посторонние ID запрещены. Вызовы модели и получение её ответов **не автоматизированы** этим скриптом; имитацию нельзя выдавать за замер LLM.

Сравнение двух внешних прогонов разрешается только при совпадении SHA256 эталона, версии методики и режима получения ответов. Отчёт показывает TP/FP/FN/TN, Precision/Recall, неопределённые решения, ошибки по ID и изменения по совпадающим случаям. Отсутствие положительных примеров или предсказаний даёт *не определено*, а не ложные 100%.

## Что проверяется в рабочем коде

- Сверка вызывает **существующую** mint.evidence.verify_comparison(), а не вторую реализацию проверки норм. Речь о проверке доказательств, не о юридическом выводе.
- Для матриц используются **те же** mint.template_draft.covered_refs() и unresolved_candidates(), что и при формировании черновика. Источник засчитывается только при наличии процитированного фрагмента *созданного текста*. Отсутствие подтверждения — *кандидат на проверку*, не автоматически пропущенное обязательное требование.
- tests/run_all.py запускает сценарии в CI. Это быстрое **unit/integration-level** испытание логики с заранее заданными ответами, а не полный аудит документа с реальной моделью.

## Известные ограничения (обязательно учитывать)

1. Нормативный конфликт теперь требует scope_quote из проверяемого текста. **Явное отрицание** в этой цитате блокирует подтверждение; но даже настоящая цитата о **другой функции** может ошибочно использоваться моделью для вывода о применимости. Эталоны E37/E39 сохраняют такие ложные срабатывания. Ни цитата, ни модельное объяснение не удостоверяют юридическую силу источника.
2. Один лишь source ID больше **не засчитывается**: в D05:R1 требование процитировано, но в тексте его нет, и оно появляется в списке для проверки. Однако *достоверная цитата из текста не означает смыслового соответствия конкретному требованию*: D06:R1 намеренно остаётся пропущенным, несмотря на найденную цитату о другой интеграции.
3. Смена метода оценки на document-quality-v2 и обновление набора меняют его SHA256: **не сопоставляйте напрямую отчёты PR #20 и PR #21**. Для честного сравнения нужны одинаковая разметка, версия метода и входные данные; замеры на модели выполняются отдельно. Измерение на 40 искусственных случаях не оценивает поиск по рабочей Вики, применимость сложных корпоративных нормативов или оформление реальных Word-шаблонов.
4. Чтобы доказать улучшение на практике, нужна небольшая **закрытая** эталонная выборка реальных задач: вручную размеченные истинные нарушения, ложные замечания и обязательные требования черновика; одинаковые версии документов и база, контроль версии LLM/промптов, повторные прогоны. Никаких рабочих документов, цитат, ключей или результатов в публичный GitHub.

**Правило принятия изменений:** на одинаковых задачах ложных замечаний должно стать меньше **без потери** настоящих нарушений и применимых требований. До подтверждения эффект формулируется только как «механизм прошёл искусственные тесты».
