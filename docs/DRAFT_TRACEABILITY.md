# Прослеживаемость: Word ↔ основания

На вкладке «Составление документа», рядом с чатом редактирования, есть
**«Требования и их отражение в Word»** с двумя представлениями одного набора
данных: по разделам Word и по выбранным документам-основаниям.

Для каждого извлечённого требования показаны оригинальная цитата, исходный
файл/раздел, оценка применимости и ссылка на разделы Word.

Нужно различать четыре состояния:
- **Текстовое отражение найдено**: в одном из принятых результатов заполнения
  есть буквальный фрагмент, указанный моделью в `coverage`. Это НЕ гарантия
  полной/точной реализации требований;
- **Источник процитирован, но якорь отсутствует**: модель назвала требование,
  однако не указала достоверный фрагмент созданного текста;
- **Кандидат для раздела**: требование подавалось в контекст поля, но не
  доказано, что вошло в документ;
- **Нет связи / неясна применимость / другой участник**: требование сохраняется
  в списке оснований для рассмотрения, но в формирование автоматически не попало.

Числа на панели означают только **извлечённые** пункты и найденные текстовые
якоря. Они не измеряют полноту извлечения относительно всего оригинального
документа. Настоящие пропуски и смысловые ошибки по-прежнему выявляются
экспертом (механизм PR22), а не по одному счётчику.

Никаких новых LLM-запросов или параллельных систем проверки UI не добавляет:
связи вычисляются на уже собранных `requirements`, `section_plan`,
`results.confirmed_refs`. Возвращаемые группировки используют одну функцию
`build_traceability`. Данные основания не записываются в новый индекс.

После исправления Word через чат текстовые якоря старой версии нельзя считать
актуальными; следующий PR добавляет явную пометку и переход к редактированию.
